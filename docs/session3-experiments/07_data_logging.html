6 · Data Logging: From Console to CSV

Block 2 · Learning goals: Collect every trial as a dictionary, gather them in a list, and save them as a CSV logfile with a unique name.

Data that evaporates

Exercise 6 ended with your experiment printing a line per trial: stimulus, response, correct answer, reaction time. If you then closed PsychoPy, the data would cease to exist. Real experiments write their rows to a file, and the file format of choice is CSV, comma separated values: plain text, one row per line, readable by R, Excel, and everything else you will ever analyse data with.

The plan has three steps. During the experiment, collect each trial’s facts. After the loop, turn the collection into a table. Save the table to a file whose name cannot collide with anyone else’s.

One trial, one dictionary

A trial is a set of labelled facts, and you met the container for labelled facts in the last chapter: the dictionary. One trial becomes one dictionary; the whole experiment becomes a list of dictionaries, built with the .append() you have used since Session 1. A miniature you can run in a plain script, no window needed:

rows = []                       # before the loop: an empty list

for trial in [1, 2, 3]:
    rows.append({'trial': trial, 'rt': trial * 0.5})

print(len(rows))
print(rows[0])
3
{'trial': 1, 'rt': 0.5}

Same script. What does print(rows[2]['rt']) show?

Index 2 of the list is which trial? Count from zero, then look up the 'rt' key in that dictionary.

1.5. Two lookups chained: rows[2] fetches the third dictionary from the list, position first, and ['rt'] fetches one value from it, key second. List of dictionaries: position finds the trial, name finds the fact. This is the exact shape your experiment’s data takes today.

From rows to a table: pandas

A list of dictionaries becomes a table in one line, using pandas, the Python library for tabular data. Today we’ll use two lines of it:

import pandas as pd

logfile = pd.DataFrame(rows)
print(logfile)
   trial   rt
0      1  0.5
1      2  1.0
2      3  1.5

The dictionary keys became column names, and each dictionary became a row. Saving the table is one more line:

logfile.to_csv('logfile.csv', index=False)

The index=False leaves out the bold row numbers on the left, which belong to pandas, not to your data. Run it, then find logfile.csv next to your script and open it. Suddenly you have a .csv file you would be able to read in with R.

A name that cannot collide

One flaw remains, and it is a data-destroying one.

🤔 Think first

Your experiment saves to 'logfile.csv', a fixed name. Participant one is tested, then participant two. What happens to participant one’s data?

Check your thinking

It disappears. The second save writes a file with the same name in the same folder, which silently replaces the first. The experiment would appear to work perfectly while destroying one dataset per participant. The filename must be different for every run.

Two ingredients make a filename unique: the participant code you already generate, and a timestamp from PsychoPy’s data module, which joins the import line:

from psychopy import visual, event, core, gui, data

date = data.getDateStr()
logfile_name = f'logfiles/logfile_{participant_id}_{date}.csv'

data.getDateStr() returns the current date and time as a compact string, so logfile_name becomes something like logfiles/logfile_P48213_2026-09-29_09h41.22.csv. Two participants can no longer produce the same name.

A home for the logfiles

The filename above puts every logfile in a logfiles/ folder, so the CSVs do not pile up next to your script and stimuli. You could create the folder by hand, but there is a reason to let the script guarantee it instead: if the folder is missing, the save fails at the very end of the experiment, after all the trials have run, and the rows are lost with it. One line from the os module removes that risk forever:

import os

os.makedirs('logfiles', exist_ok=True)

exist_ok=True means: create the folder, and if it already exists, do nothing. Safe to run every time, on every computer the experiment ever moves to.

Into the rabbit script

The pieces land in three places, and only three. In the setup: the imports, the folder, the empty list. Inside the trial loop, after the feedback: one append, carrying both the participant facts and the trial facts. After the loop: build the table and save it, before the goodbye.

# --- setup ---
os.makedirs('logfiles', exist_ok=True)
date = data.getDateStr()
logfile_name = f'logfiles/logfile_{participant_id}_{date}.csv'

rows = []

# --- inside the trial loop, after the feedback ---
    rows.append({'id': participant_id,
                 'language': language,
                 'handedness': handedness,
                 'stimulus': image,
                 'key': key,
                 'correct_key': correct_key,
                 'rt': rt})

# --- after the loop ---
logfile = pd.DataFrame(rows)
logfile.to_csv(logfile_name, index=False)
Log the consent

Your experiment begins with an informed consent dialog, and consent is a fact about the data, so it belongs in the logfile. The pattern is the one you know: the dialog’s OK button becomes a variable, and the variable becomes a column.

if consent_box.OK:
    consent = 'yes'
else:
    core.quit()

Then add 'consent': consent to the dictionary in rows.append({...}), and every row of the logfile now certifies that this participant agreed.

# --- inside the trial loop, after the feedback ---
    rows.append({'id': participant_id,
                 'language': language,
                 'handedness': handedness,
                 'stimulus': image,
                 'key': key,
                 'correct_key': correct_key,
                 'rt': rt})

One thing to notice about this column: it will say yes on every row of every file you ever collect. A participant who declines is sent out by core.quit() before a single trial runs, so no file is written for them, and that is exactly right: no consent, no data. The column is there so that anyone who opens the file later, your group, your teacher, or you in December, can see that consent was obtained, without hunting for a separate piece of paper.

Note that the participant columns repeat identically in every row. That looks wasteful and is exactly right: each row of a data file should stand on its own, so that R can group, filter, and compare without consulting a second file.

Good to know: escape loses the rows

The save happens once, after the loop. If the experiment stops early, through the escape key’s core.quit() or a crash, the rows collected so far are never written. For our purposes that is acceptable: an aborted session is an incomplete dataset anyway. If you ever need crash-proof logging, the fix is saving inside the loop, once per trial, at the cost of rewriting the file repeatedly. Worth knowing, but not worth doing today.

Summary

Each trial becomes a dictionary, appended to a list; after the loop, pd.DataFrame(rows) turns the list into a table and to_csv() writes it, with index=False. The filename is built from the participant code and data.getDateStr(), so no two runs can overwrite each other, and the file lands in a logfiles/ folder guaranteed by os.makedirs(..., exist_ok=True). Participant facts repeat in every row on purpose: rows should stand on their own.
