3 · The Draw-Flip Cycle (and How to Break It)

Block 1 · Learning goals: Master the draw-flip cycle (i.e., prepare, draw, flip) and learn to recognise its three classic failure modes.

Two buffers: backstage and stage

Here is the single most important mechanic of the day. PsychoPy uses double buffering: there are two screen buffers, and you never draw directly onto the visible one. Showing a stimulus always takes three steps:

  1. Prepare: create the stimulus object: stim = visual.TextStim(win, text='Hi!'). Nothing appears.
  2. Draw: paint it onto the hidden back buffer: stim.draw(). Still nothing on screen!
  3. Flip: swap the buffers: win.flip(). The prepared image appears, all at once.

Think of a theatre: the back buffer is backstage, the front buffer is the stage. You can arrange the whole scene backstage: draw as many stimuli as you like, and flip() raises the curtain in a single instant.

Why this design?

A typical monitor redraws 60 times per second, so one frame lasts ~16.7 ms. Because the swap happens between two refreshes, stimulus onset is a single, well-defined moment: the moment of the flip. In Block 3, we will reset a clock at exactly that moment to measure reaction times.

Hello, world: the full cycle

Type and run:

from psychopy import visual, event, core

win = visual.Window(size=(1080, 720), color='black',
                    fullscr=False, checkTiming=False)

text = visual.TextStim(win, text='Hello, world!',
                       color='white', height=0.1)
text.draw()      # paint it backstage
win.flip()       # curtain up!

event.waitKeys() # pause until any key is pressed

win.close()      # close the window
core.quit()      # end the session cleanly

You should see Hello, world! in white on black, staying until you press a key. The line doing the staying is event.waitKeys(): it pauses the script until any key is pressed. Which key, and what to do with that information, becomes important later on.

The sabotage lab

Now let’s break it on purpose to figure out what’s going on in the code: three times. Each sabotage teaches you to recognise one of today’s three most common bugs before it happens to you by accident. Think first, then actually run the broken script and watch.

Note🤔 Sabotage 1: think first

Delete the line win.flip(). What will you see when you run it?

TipCheck your thinking

A blank black window. The text was drawn, but only to the back buffer, which was never swapped to the screen. Everything happened backstage; the curtain never rose. Blank screen almost always means a missing flip.

Note🤔 Sabotage 2: think first

Put win.flip() back. Now delete event.waitKeys(). What happens?

TipCheck your thinking

The text flashes for a split second and vanishes. The script runs straight on to win.close(), and closing the window takes the text with it. Every flip needs a waiting step after it: a keypress wait like before, or a timed core.wait() as in the next chapter. If this is missing, the participant sees almost nothing.

Note🤔 Sabotage 3: think first

Restore everything. Now delete the last two lines (win.close() and core.quit()). What happens after you press a key?

TipCheck your thinking

Quite possibly… nothing different! On modern PsychoPy the window usually closes anyway when the script ends. So why do we insist on those two lines? Because usually is not a word you want in an experiment: on some machines and older versions, the window lingers as a frozen zombie, and in longer scripts an un-closed window can hold resources or hide error messages. win.close() and core.quit() make the shutdown explicit and guaranteed instead of a lucky side effect.

Repair your script so all three sabotages are undone, and run it once more to prove it.

Your first debugging

You’ve now caused all three diseases, so you can diagnose them. This is the skill that saves you time all afternoon:

Your neighbour’s script runs without errors, but their window is plain black: no text, nothing. Which line have they most likely forgotten?

If draw() were missing you’d also see nothing, but the far more common culprit is the step after drawing. What raises the curtain?

win.flip(): the stimulus was prepared and probably drawn, but never swapped to the visible screen. Blank-but-running is the flip’s signature symptom. (A missing draw() produces the same blankness and is the second guess, but forgetting the flip will be today’s most common bug by a wide margin.)

Say the mantra once: prepare, draw, flip, wait. You now have the day’s core mechanic memorised.

Load up a visual stimulus

Time for your first image, and the good news is that you already know how this works. An image follows the same cycle as text; the only change is the type of stimulus you prepare. Where text uses TextStim with a text argument, images use ImageStim with an image argument naming a file:

img = visual.ImageStim(win, image='rabbit.jpg')
img.draw()
win.flip()

Prepare, draw, flip: nothing else is new. What you need is the file itself. Download the rabbit and save it in the same folder as your script:

⬇️ Download rabbit.jpg

Now modify your Chapter 3 script: after the Hello, world! screen, show the rabbit, participant-paced. Run it.

TipShow the code 
from psychopy import visual, event, core

win = visual.Window(size=(1280, 720), color='black',
                    fullscr=False, checkTiming=False)

img = visual.ImageStim(win, image='rabbit.jpg')
img.draw()
win.flip()
event.waitKeys()

win.close()
core.quit()
NoteWhere Python looks for images

'rabbit.jpg' is a relative path: Python looks for the file in the same folder as your script. If the image refuses to load, the file and the script are not sitting together. That is the most common little stumble of the day, and the fix is just moving a file.

NoteSummary

Showing a stimulus is always three steps: prepare the object, draw it to the hidden back buffer, flip the buffers to reveal it, then wait, or the participant sees nothing. The flip is a single, precisely-timed moment, which is what makes reaction-time measurement possible. And the three sabotages gave you the diagnostic table: blank screen → likely a missing flip; content flashing past → missing wait; lingering window → missing cleanup. Prepare, draw, flip, wait.
